Demo & Submission Checklist

Suggested 6–8 minute demonstration

  1. Launch (30 seconds): start the local app from its shortcut. Explain PHP runs on the laptop and SQLite saves records locally.
  2. Students (1 minute): add a fictional student, search for it, edit its section, and show invalid input handling.
  3. Tasks (1 minute): add a task with a real deadline. Explain that each task applies to all students.
  4. Submissions (1 minute): show pending and overdue, mark a row submitted, filter results, and explain the timestamp.
  5. Dashboard (30 seconds): explain expected = students × tasks and pending includes overdue.
  6. Testing and design (2 minutes): run tests; show red/green evidence and real Git commits; identify domain, application, and infrastructure folders.
  7. Postman (1 minute): show session bootstrap and student GET/POST/PUT/DELETE requests with status codes and test results.
  8. Persistence (30 seconds): stop/start the app and show records remain.

Before submission

  • Read and understand the code. Adapt it to your group's decisions and acknowledge assistance according to your course rules.
  • Confirm with the instructor that SQLite is acceptable if your section specifically expects MySQL; the provided written brief does not prescribe a database engine.
  • Add your actual group name, section, five member names, and true contribution records. Do not assign invented contributions.
  • The project repository is https://github.com/NemesioLorenzoPesigan/scholardesk-cs0053-final-project (private). The URL is in the README. Give the instructor and actual group members access before submitting the link.
  • Review actual test outputs and take required screenshots, especially the Postman runner and individual API results.
  • Record the demonstration video or give the live presentation. This package includes a script, not a completed video or presentation recording.
  • Have every member practice explaining their part and one test.
