API Documentation

Default base address: http://127.0.0.1:8053. Resource routes use /api.php?route=..., so Apache rewrite configuration is unnecessary.

Session and request format

  1. Send GET /api.php?route=session.
  2. Keep the PHP session cookie returned by the server.
  3. Read data.csrf_token. For POST, PUT, DELETE, send it as X-CSRF-Token.
  4. For POST and PUT, send Content-Type: application/json and a JSON object.

Successful responses have {"data": ...}; errors have {"error":"message"}. Query IDs must be positive integers. PUT sends all editable fields. No CORS access is enabled. The application is local and has no API account authentication.

Student body

{
  "student_number": "2026-1234",
  "full_name": "Sample Student",
  "email": "sample@example.test",
  "course": "BS Computer Science",
  "year_level": 2,
  "section": "SE31"
}

Limits: student_number 30, full_name 100, email 150, course 80, section 30 characters. Year is an integer from 1 through 6.

Task body

{
  "title": "API laboratory",
  "subject": "CS0053",
  "due_date": "2026-12-01",
  "description": "Prepare API tests."
}

Limits: title 120, subject 80, description 2000 characters. Deadline must be a real YYYY-MM-DD date. Past dates are allowed so overdue work can be recorded.

Submission body

{ "student_id": 1, "task_id": 1, "status": "submitted" }

Both records must exist. Use status pending to clear a submission. The server chooses the submission timestamp. Repeating submitted does not change it.

Postman workflow

For Postman v12 Local Mode, open this project folder and use the converted YAML collection at postman/collections/ScholarDesk - Local API Tests. A 2.1 JSON export is also included in this docs folder for compatibility; Postman may offer to upgrade that export. The v3 local structure follows Postman’s Native Git documentation. This project is not linked to a cloud workspace.

Open ScholarDesk.postman_collection.json from this docs folder in Postman. Keep its base_url set to http://127.0.0.1:8053. Run requests 01–12 in order with cookies enabled. The collection captures the session token and newly created record IDs, asserts status codes, changes submission state, and removes the fictional records it created. On a failed run, inspect which request failed before rerunning cleanup. The API test client and Postman must consistently use the same host (127.0.0.1 rather than alternating with localhost).
